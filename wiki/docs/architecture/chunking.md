# 结构感知切分

对应代码：`app/core/chunker.py`、`app/core/loader.py`、`app/core/text_utils.py`

切分质量是整个 RAG 的地基。这一页解释三级兜底策略、表格为什么必须当原子块，
以及"内容不丢失"是怎么被测试保证的。

---

## 三级兜底策略

按优先级依次尝试，前一级能切就不到下一级：

| 级别 | 依据 | 适用情况 |
| --- | --- | --- |
| 1. 标题层级 | Markdown 标题结构 | 规范的 Markdown 文档 |
| 2. 段落 | 空行分隔 | 无标题或用纯文本 |
| 3. 句子 | 中英文句末标点 | 单段落超长（如整篇无换行的 PDF 抽取文本） |

每个片段都会带上**章节路径**（如 `保养 > 首轮保养 > 周期表`）写入 metadata。
这不是装饰——[混合检索](retrieval.md) 里的「章节命中」信号就依赖它，因为章节标题比正文更凝练。

---

## 核心设计：Markdown 表格作为原子块

**为什么**：表格（保养周期表、故障码表）天然是「行 = 一条完整事实」的结构。
如果按字符数硬切，会出现两个真实缺陷：

1. 定义所在的行被切到下一块，块内只剩一堆没有表头的数字；
2. 「重叠（overlap）」把上一段的散文拼到了表格行前面，污染了表格语义。

**怎么处理**：

- 表格**不与段落混合**，作为独立原子块；
- 超长表**按行切分**，并且**逐片重复表头**——每一片都能自解释；
- 当前块以表格开头时，**不做重叠**（避免把散文粘到表格前）。

这一条在 [实测记录第二轮](../evaluation/results.md) 里有直接的修复前/后对比数据。

## 重叠与碎块合并

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `CHUNK_SIZE` | `600` | 目标片段字符数 |
| `CHUNK_OVERLAP` | `80` | 相邻片段重叠字符数（代码内保证 `< CHUNK_SIZE`） |
| `CHUNK_MIN_CHARS` | `80` | 小于该长度的碎块**并入前一块**，避免产生孤立碎片 |

!!! warning "切分器不再有硬编码下限"
    早期版本切分器内部有一层硬编码下限，会**静默覆盖**用户配置
    （例如你在 `.env` 里配了 `CHUNK_SIZE=80`，实际却按 120 切）。
    现在下限已移除，统一由 `Settings.normalize()` 处理：低于 120 会纠正，
    并在 `/health` 的 `config_warnings` 里提示。

## 多格式加载

| 格式 | 依赖 | 缺失时的行为 |
| --- | --- | --- |
| `.md` / `.markdown` / `.txt` | 内置 | — |
| `.pdf` | `pypdf` | 返回**明确错误信息 + 安装命令**，不静默跳过 |
| `.docx` | `python-docx` | 同上 |

```bash
pip install pypdf            # 解析 PDF
pip install python-docx      # 解析 DOCX
```

## 切分质量怎么验证

不需要大模型，纯逻辑断言即可覆盖：

```bash
python tests/smoke_test.py
```

其中与切分相关的断言包括：

- 多章节文档**产出多片段**；
- 切分**可复现**（同样输入两次结果一致）；
- **内容不丢失**（拼接后能还原原文的关键内容）；
- **表格不被切断**（表格行与表头在同一片段内）。

如果用人工抽查，可以预览向量库里实际的片段：

```bash
curl "http://127.0.0.1:8000/api/v1/chunks/preview"
```
